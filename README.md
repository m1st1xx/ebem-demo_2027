## 1. Что находится в репозитории

| Файл | Назначение |
|---|---|
| `isp.sh` | Базовая настройка узла ISP |
| `hq-rtr.sh` | Базовая настройка маршрутизатора HQ-RTR |
| `hq-srv.sh` | Базовая настройка сервера HQ-SRV |
| `hq-cli.sh` | Базовая настройка клиента HQ-CLI |
| `br-rtr.sh` | Базовая настройка маршрутизатора BR-RTR |
| `br-fw.sh` | Базовая настройка межсетевого экрана BR-FW |
| `br-srv.sh` | Базовая настройка сервера BR-SRV |

Скрипты настраивают только перечисленные в них параметры. Не считайте, что они автоматически выполняют все задания демонстрационного экзамена.

## 2. Подготовка VMware Workstation

1. Установите VMware Workstation и подготовьте ISO-образ Debian, который будете использовать на стенде.
2. Создайте виртуальную машину для `ISP` по шагам ниже.
3. Установите Debian и убедитесь, что система запускается.
4. Создайте остальные виртуальные машины или клонируйте подготовленную машину, затем настройте для каждой имя и сетевые адаптеры.
5. Для внутренних сетей используйте **LAN Segment**, а не VMnet.
6. Перед запуском скриптов проверьте имена сетевых интерфейсов: сценарии используют `ens33`, `ens37` и `ens38`.

## 7. Сетевые подключения стенда

Создайте следующие LAN Segment и подключите к ним указанные адаптеры:

| LAN Segment | Подключённые интерфейсы | Назначение |
|---|---|---|
| `LS-HQ-UPLINK` | ISP `ens37`, HQ-RTR `ens33` | Связь HQ с ISP |
| `LS-BR-UPLINK` | ISP `ens38`, BR-RTR `ens33` | Связь BR с ISP |
| `LS-HQ-LAN` | HQ-RTR `ens37`, HQ-SRV `ens33`, HQ-CLI `ens33` | Внутренняя сеть HQ |
| `LS-BR-TRANSIT` | BR-RTR `ens37`, BR-FW `ens33` | Связь маршрутизатора и firewall BR |
| `LS-BR-LAN` | BR-FW `ens37`, BR-SRV `ens33` | Внутренняя сеть BR |

Для первого адаптера ISP (`ens33`) выберите **NAT**, если стенду нужен доступ в интернет. LAN Segment — это изолированный виртуальный коммутатор: он сам не выдаёт IP-адреса и не обеспечивает выход в интернет.

### Порядок адаптеров

| Виртуальная машина | Адаптер 1 | Адаптер 2 | Адаптер 3 |
|---|---|---|---|
| ISP | `ens33` — NAT | `ens37` — `LS-HQ-UPLINK` | `ens38` — `LS-BR-UPLINK` |
| HQ-RTR | `ens33` — `LS-HQ-UPLINK` | `ens37` — `LS-HQ-LAN` | — |
| HQ-SRV | `ens33` — `LS-HQ-LAN` | — | — |
| HQ-CLI | `ens33` — `LS-HQ-LAN` | — | — |
| BR-RTR | `ens33` — `LS-BR-UPLINK` | `ens37` — `LS-BR-TRANSIT` | — |
| BR-FW | `ens33` — `LS-BR-TRANSIT` | `ens37` — `LS-BR-LAN` | — |
| BR-SRV | `ens33` — `LS-BR-LAN` | — | — |

**Важно:** `HQ-RTR` использует VLAN-подинтерфейсы на `ens37`, а `HQ-SRV` — VLAN 100 на `ens33`. Сегмент `LS-HQ-LAN` должен передавать тегированные кадры 802.1Q между виртуальными машинами. Проверьте это на используемой версии VMware. Если VLAN trunk не проходит, потребуется изменить виртуальную топологию или среду виртуализации.

## 8. Запуск скриптов

1. Скопируйте репозиторий на соответствующие виртуальные машины либо перенесите нужный скрипт.
2. Проверьте настройки каждого скрипта до запуска.
3. Запускайте скрипт **только на соответствующем узле**.

Пример:

```bash
sudo apt update
sudo apt install -y git
git clone https://github.com/m1st1xx/ebem-demo_full.git
cd ebem-demo_2027
less isp.sh
chmod +x isp.sh
sudo ./isp.sh
```

На каждой машине используйте свой файл:

| Машина | Скрипт |
|---|---|
| ISP | `isp.sh` |
| HQ-RTR | `hq-rtr.sh` |
| HQ-SRV | `hq-srv.sh` |
| HQ-CLI | `hq-cli.sh` |
| BR-RTR | `br-rtr.sh` |
| BR-FW | `br-fw.sh` |
| BR-SRV | `br-srv.sh` |

Скрипты меняют сетевые настройки и системные параметры. Запускайте их на снимке виртуальной машины, которую можно восстановить, и только после проверки содержимого.

## 9. Проверки и устранение проблем

Проверить имена интерфейсов и адреса:

```bash
ip -br link
ip -br address
ip route
```

Проверить связь с соседним узлом, используя адрес из таблицы:

```bash
ping -c 4 172.16.1.1
```

Если интерфейсы называются не `ens33`/`ens37`/`ens38`, поправьте соответствующие скрипты перед запуском. Также проверьте, что адаптеры подключены к правильным LAN Segment и что на всех участниках одного сегмента выбрано одно и то же имя.
